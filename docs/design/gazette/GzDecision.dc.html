ADR 02 · Platform runtime

One runtime for thirty micro-frontends, via Import Maps

Teams should ship independently. Users should not download the same framework thirty times.

Context

More than thirty micro-frontends, owned by different teams, render inside one product. [Your words: what was going wrong before, e.g. load time, version drift, duplicated dependencies.]

Options considered

OptionForAgainst
Bundle shared code per appSimple, fully independentDuplicate downloads; version drift
Build-time compositionOne optimised bundleTeams can no longer release alone
Import Maps, one runtimeWeb standard; shared once; independent releasesNeeds a contract for shared versions

[Confirm or replace the options you actually weighed.]

Decision

All micro-frontends load shared dependencies from one platform runtime, resolved through Import Maps. The platform team owns the map and its upgrade policy.

Consequences

Better

  • Shared code is downloaded once.
  • Teams release on their own schedule.
  • [A measured result, if you have one.]

Harder

  • Shared upgrades need coordination.
  • The runtime is now critical infrastructure.
